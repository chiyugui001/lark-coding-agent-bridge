# COT 过程消息 concise 档设计

> 状态：可用（v0.7.x，提交 4144a17）。只读用户的默认过程档位。

## 背景

飞书过程消息（COT bubble）需要在两个极端之间取平衡：

- **全量展示**（brief/detailed）：模型的原始思考常包含内部元指令（"No ExitPlanMode
  needed"）和本机细节（绝对路径、命令、仓库结构），既冗长又有信息泄露面；
- **纯阶段条**（minimal）：只有"理解用户问题 → 思考中 → 整理回复"，用户完全
  感知不到任务在做什么，体验过于黑盒。

concise 档参考 FastGPT 的过程展示：有真实的过程感，但不倾倒思考全文。

## 档位总览

| 档位 | 思考 | 工具 | 中间正文 | 适用 |
|---|---|---|---|---|
| off | — | — | — | 关闭过程消息 |
| minimal | 无（仅阶段条） | 仅工具名 | 隐藏 | 最严格 |
| **concise** | **每段一句结论（≤200 字）** | **仅工具名** | **隐藏** | **只读用户默认** |
| brief | 全文 | 摘要标题（含路径） | 全文 | 受信用户 |
| detailed | 全文 | 摘要 + 参数 + 输出 | 全文 | 调试 |

## concise 规则

### 1. 思考：每段一句结论

每段 reasoning burst 缓冲，在 burst 结束（工具调用/正文/终止事件）时发布**一句话**：

1. 按中文句读（。！？!? + 换行）切句；
2. **过滤元指令句**（`ExitPlanMode|plan mode|bridge_mode_notice|批准|approval|final message|report findings|no implementation|只读模式` 等）——这类句子是模型的自我交代，对用户无价值；
3. 优先取**最后一句含中文的**有效句（中文答中文用户，结论句通常是中文）；
4. 无中文则取最后一句有效句；全被过滤则取最长句；
5. 截断上限 **200 字**（带 …）。

### 2. 工具：仅名字

`调用工具: Read` / `调用工具: Grep`（带工具图标），参数、路径、命令、输出全部不出现。
结果只显示 `工具调用已完成/失败`。禁止路径进入标题（测试断言标题不含 `D:` 与 `/`）。

### 3. 阶段条 + 耗时

```
● 理解用户问题
● 思考中            ← 思考摘要句挂在此阶段下
● 调用工具: Read → 工具调用已完成
● 整理回复
✓ 任务完成（耗时 16.0s）   ← 失败为 任务失败（耗时 …）
```

耗时 = 事件流消费起点到终止事件的实际秒数，作为终止前的最后一个 STEP 展示。

### 4. 权限联动

发送者解析为 **read-only** 档时，无视全局配置强制使用 concise
（`off` 仍可完全关闭）；workspace/full 用户按全局 `preferences.cotMessages` 配置。

## 实现位置

- `src/bot/cot.ts` — `consumeCotEvents` 的 minimal/concise 分支、`conciseSummary()`
  （选句 + 元句过滤 + 上限）、耗时 STEP；
- `src/config/schema.ts` — `CotMessagesMode` 五档枚举与归一化；
- `src/bot/channel.ts` — 按发送者权限解析强制档位；
- `tests/unit/bot/cot.test.ts` — minimal/concise/选句/路径泄露/耗时用例。

## 已知边界

- 选句基于启发式（元词过滤 + 中文优先），偶发选中非最优句属于体验问题而非
  泄露问题——元词表可按需扩充；
- 英文思考的句读只按换行与 !? 切分（英文句点会在标识符中间误切，如
  `README.md`，故不参与切分），长句依赖 200 字上限兜底。
